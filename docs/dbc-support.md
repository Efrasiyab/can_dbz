# DBC support profile

The initial DBC adapter is deliberately incremental. By default, unsupported statements fail with a diagnostic and source line/column. Call `parseWithOptions` with `preserve_unsupported_statements = true` to retain unsupported single-line statements in `Document.dbc.opaque_statements`; the default `parse` API remains strict.

## Export requirements

`dbc.write` omits document names, descriptions, extensions, and unknown `dbc` metadata because DBC has no matching fields. Use `dbc.writeWithDiagnostics` to receive warnings for those omissions. Referenced CAN JSON value tables are expanded into per-signal DBC values, so table names are not retained. Export fails with `error.UnsupportedConstruct` for constructs the writer cannot safely encode; diagnostics identify each blocker.

- More than one bus, or a bus not named `can0` (or with a description, protocol or attributes).
- Descriptions on the bus, node or message (only signal `CM_` comments are supported).
- More than one transmitter on a message, or message receivers.
- Attributes other than bounded message-scoped integers, including bus, node, signal, and document assignments.
- Names that are not valid DBC identifiers.

Missing signal `minimum`/`maximum` do not block export; they are written as `[0|0]`.

Malformed supported declarations (such as `BO_`, `SG_`, `VFrameFormat`, `VAL_`, `SG_MUL_VAL_`, and `SIG_VALTYPE_`) remain errors even when preservation is enabled. Export also rejects metadata that the current DBC profile cannot represent (for example bus/message descriptions and multiple buses). The adapter is not yet a general-purpose DBC converter.
